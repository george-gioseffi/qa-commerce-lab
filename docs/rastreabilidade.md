# Rastreabilidade revisada e lacunas

Esta matriz foi revisada a partir das asserções dos testes listados. Ela cobre apenas os recortes descritos, não a totalidade de cada área. Os caminhos e títulos são verificados por `npm run ai:traceability`; a existência de um teste não comprova sua execução. Consulte os artefatos do CI do commit que está sendo avaliado.

| ID | Requisito e risco | Testes revisados | Lacuna conhecida |
|---|---|---|---|
| AUTH-01 | Credenciais e tokens inválidos ou expirados devem ser recusados; risco de acesso indevido. | `api.spec.ts`: `logs in with valid credentials and rejects wrong password or unknown email`; `enforces JWT authentication on /api/auth/me and rejects invalid/expired tokens`. `auth.spec.ts`: `invalid stored token recovers cleanly to logged-out state`. | Expiração durante a sessão ainda não foi exercitada explicitamente pela interface. |
| CAT-01 | Filtros e falhas devem ser apresentados corretamente; risco de busca enganosa. | `api.spec.ts`: `lists products and supports search, category, combined filters, and empty results`. `catalog.spec.ts`: `displays error banner when catalog API fails`. | Regras para espaços e caracteres especiais na busca precisam ser definidas e testadas. |
| CART-01 | Quantidade e valor do carrinho devem ser consistentes; risco de perda de item ou valor incorreto. | `api.spec.ts`: `validates invalid quantities, missing products, and missing cart items`. `cart-checkout.spec.ts`: `updates cart total, persists across reload, and removes item`; `shows error and preserves cart total when quantity update fails`. | Concorrência de alteração no carrinho em múltiplas abas ainda não tem teste E2E dedicado. |
| ORDER-01 | Conflitos conhecidos não devem gerar pedido duplicado ou incorreto. | `api.spec.ts`: `prevents duplicate orders when two concurrent checkouts run for the same user`; `rejects checkout if the cart quantity changes after it was read`; `prevents overselling when stock drops before checkout`; `allows at most one order when two users compete for the last unit`. | Uma retentativa após perda da resposta ainda requer contrato de idempotência e cenário específico. |
| A11Y-01 | Áreas principais devem permitir navegação acessível. | `accessibility.spec.ts`: `home page has no critical or serious accessibility violations`; `keyboard navigation reaches search, filter, and auth controls`. | Inspeção de foco visível e leitor de tela permanece manual; axe não comprova acessibilidade integral. |
| CONTRACT-01 | Respostas reais da API devem respeitar os schemas OpenAPI 3.0 documentados. | `api.spec.ts`: `validates live API responses against OpenAPI 3.0 schemas in docs/openapi.yaml`; `ignores role escalation on register and never exposes passwordHash`. | Validação de `requestBody` e headers via middleware OpenAPI completo em runtime ainda não é usada. |
| SAFETY-01 | Scripts de reset e seed destrutivos não podem atingir bancos não descartáveis. | `safety.test.mjs`: `a test reset requires a local test database and exact confirmation`. `seed-policy.test.ts`: `seed reset rejects an unconfirmed, non-test or remote target before connecting`. | Auditoria contínua de novos scripts de banco adicionados ao repositório permanece manual. |

Os arquivos de API estão em [`apps/backend/src/test`](../apps/backend/src/test/), os E2E em [`tests/e2e/tests`](../tests/e2e/tests/) e os de segurança em [`scripts`](../scripts/) e [`apps/backend/prisma`](../apps/backend/prisma/). A execução do CI em cada commit do PR pode ser conferida diretamente na aba Actions do repositório.

`npm run ai:scenarios` gera propostas para as lacunas acima em `reports/scenario-proposals.json`, com objetivo, pré-condições, passos, resultado esperado, risco e prioridade. A geração é **determinística e baseada nesta curadoria**, não usa modelo externo nem altera a suíte; cada proposta exige revisão e implementação antes de ser considerada teste. As sugestões por palavras em `npm run ai:matrix` também não provam cobertura.
